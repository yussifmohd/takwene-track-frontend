## Phase 0 – Foundation & health check (`001-project-foundation-and-health-check`)

### What was built
A React 19 + TypeScript + Vite single-page app with the app shell, a typed API client generated
from the backend's OpenAPI contract, and one page: a system status page showing API and database
health. Also an nginx container (port 8081) that serves the app and proxies `/api` to the API, and CI.

### Important files
| Path | What it does |
|---|---|
| `src/api/client.ts` | `apiFetch`: the only way to call the API (base `/api`, JSON, token hook, `acceptStatuses`); errors become `ApiError`, network failures `ApiError(0)`. |
| `src/api/problem.ts` | ProblemDetails type, `ApiError`, `parseProblem`, `getFieldErrors` (forms), `describeError` (toasts/error states). |
| `src/api/schema.d.ts` | Types generated by `npm run gen:api` from the backend contract (never hand-edited). |
| `src/api/health.ts` | `getHealth`: treats `503` as data (an unhealthy report), not an error. |
| `src/features/health/hooks/useHealthQuery.ts` | TanStack Query: key `["health"]`, refetch every 30 s while visible, 1 retry. |
| `src/features/health/components/HealthCard.tsx`, `LevelMeter.tsx` | Skeleton while loading, ErrorState with Retry, or the report with a level meter and per-check durations. |
| `src/components/AppShell.tsx` | Header, skip link, main navigation (Tracks/Artists marked coming soon), `<Outlet/>`. |
| `src/components/UserText.tsx` | Renders user-entered text with `dir="auto"` (Arabic/Latin). |
| `src/components/ErrorState.tsx`, `PageHeader.tsx`, `NotFoundPage.tsx` | Shared states and page heading. |
| `src/router.tsx`, `src/main.tsx` | Route tree; providers (QueryClient, router, Toaster). |
| `src/index.css` | Design tokens (indigo ink, saffron accent, teal/rose status, Readex Pro), dark mode via `prefers-color-scheme`. |
| `src/test/` | MSW server (`onUnhandledFrame: "error"`), render helpers, setup. |
| `nginx/default.conf.template`, `Dockerfile`, `docker-compose.yml` | Non-root nginx on 8081, `/api` → `http://api:8080`, CSP and security headers, joins `trackmgmt-net`. |
| `scripts/check-bundle-size.mjs`, `.github/workflows/frontend-ci.yml` | 250 kB gzip budget; CI runs lint, typecheck, tests, build, budget. |

### Request flow: status page
`HomePage` → `HealthCard` → `useHealthQuery` → `getHealth` → `apiFetch("/health", { acceptStatuses: [503] })`
→ `fetch("/api/health")` → nginx proxies to the API → JSON report → `HealthCard` renders the
level meter. A non-503 error or unreachable API → `ApiError` → `ErrorState` with Retry.

### Key decisions and why
- **Types from the backend contract** so the client cannot drift from the API silently.
- **Server state in TanStack Query only**; no copies in stores.
- **Same-origin `/api` through nginx**: no CORS in production, one CSP.
- **Every state designed** (skeleton shaped like the content, error with Retry).

### How to run and test
Start the backend stack first, then `docker compose up --build` → `http://localhost:8081`.
Dev server: `npm ci && npm run dev` (proxies `/api` to `localhost:8080`). Tests: `npm test`
(19 at the end of Phase 0); also `npm run lint`, `npm run typecheck`, `npm run build`.

### Known limitations
- Only the status page; Tracks and Artists are placeholders.
- Fonts load from Google Fonts (allowed in the CSP).

## Phase 1 – Admin sign-in & session (`002-jwt-authentication-and-authorization`)

### What was built
A sign-in page, a persisted session, a route guard for protected pages, an account page, a header
menu (Sign in / email + Sign out), and automatic sign-out on token expiry, on any 401 from the
API, and when another tab signs out.

### Important files
| Path | What it does |
|---|---|
| `src/stores/authStore.ts` | zustand session `{ accessToken, expiresAt, email, roles }` persisted as `trackmgmt.session` (v1); zod-validated on load; key removed when signed out; `signOutReason` kept in memory only. |
| `src/lib/authSetup.ts` | Wires `apiFetch`: attach the token only while valid; 401 on an authenticated call → `signOut("rejected")`; follows other tabs via the `storage` event. |
| `src/api/auth.ts` | `login` (with `skipAuthHandling`, since a 401 there means wrong credentials) and `getCurrentUser`. |
| `src/features/auth/pages/LoginPage.tsx` + `schemas.ts` | react-hook-form + zod; generic message on 401 (email kept, password cleared + focused); 400 → field errors; 429 → wait time from `Retry-After`; unreachable API message. |
| `src/features/auth/redirect.ts` | `safeRedirect`: only same-origin paths as the return address; `loginPathFor`. |
| `src/features/auth/components/RequireAuth.tsx` | Layout route: signed out → `/login?redirect=<current path>`. Routes under it carry `handle.requiresAuth`. |
| `src/features/auth/pages/AccountPage.tsx` + `hooks/useCurrentUserQuery.ts` | `GET /api/auth/me`: email, role, when the session ends. |
| `src/features/auth/components/AuthMenu.tsx` | Header control; signing out on a protected page first navigates to `/` (with `flushSync`). |
| `src/features/auth/components/SessionWatcher.tsx` | Expiry timer + focus/visibility check, removes `["auth"]` queries, toast saying why the session ended. |

### Request flow: signing in
`LoginPage` (submit) → zod validation → `useLoginMutation` → `login()` → `apiFetch("/auth/login", { method: "POST", skipAuthHandling: true })`
→ nginx → API. On 200: `signIn(session)` stores it (persisted), the page re-renders as
authenticated and `<Navigate>` goes to `safeRedirect(redirect)`. Later calls get
`Authorization: Bearer …` from `getValidAccessToken()`. On 401 the form shows the generic message.

### Key decisions and why
- **Session in localStorage** (agreed trade-off): survives reloads; mitigated by the CSP, no
  `dangerouslySetInnerHTML`, 60-minute tokens, and removal on sign-out. Documented in the README.
- **Sign-out on 401 everywhere except login**, so an expired or revoked token never lingers.
- **Open-redirect protection** on `?redirect=`.
- **`RouterProvider` from `react-router/dom`**, required for `flushSync` (fixes a sign-out race found in a real browser).

### How to run and test
Both compose stacks up → `http://localhost:8081/login`, sign in with `ADMIN__EMAIL`/`ADMIN__PASSWORD`
from the backend `.env`. Tests: `npm test` (81 at the end of Phase 1).

### Known limitations
- No refresh: after 60 minutes the user signs in again.
- Token readable by script on this origin (see the trade-off above).
- jsdom tests cannot show navigation timing; real-browser checks were done with a throwaway
  script, not an automated E2E suite.
